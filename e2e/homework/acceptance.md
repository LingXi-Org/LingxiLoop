# Homework acceptance and failure inventory

Written before implementation. All fixtures are synthetic. Integration model responses may be scripted to exercise host validation and transactions; only `--live-homework` can claim model acceptance. Never write mastery, report, or submission rows to manufacture a live pass.

| Boundary | Required failures and recovery |
| --- | --- |
| Teacher publication | A student or another teacher cannot confirm the initiating teacher's card. Stale revisions, unsaved edits, pending/invalid material validation, forged hashes and reused idempotency keys with changed content reject. Publishing creates no activity or mission. Published requirements stay frozen. |
| Existing teacher runtime | An existing product-managed teacher agent with a persisted v3 prompt must receive the current managed teacher instructions on its next runtime binding, so retired objective/activity instructions cannot survive an upgrade. An ordinary non-managed agent must retain its own custom prompt. |
| Private context | Each homework/student pair resumes one private student/agent thread. Different homework, student, course and tenant are isolated. Teacher/peer never join. Revoked membership, unavailable agent, changed bound agent and draft homework reject even on resume. |
| Learning participation and truthful reports | Only a committed human text/attachment in the learner's bound private homework conversation counts as participation. Empty threads, assistant-only, foreign-learner and other-homework records do not. Any genuine record permits report generation and submission without an assessment tool call, mastery threshold, minimum duration or extra message. Missing criteria, uncertainty and aided repetition remain explicit report findings. Published assistant commentary and public explanations must reach the assistance context, including text/reasoning parts omitted from ordinary native answer text. A malformed or ungrounded model result may produce an explicitly unverified factual report, never fabricated model conclusions. Authorized learning/answer attachments that cannot be extracted remain explicit unverified limitations; permission, identity, unsafe access and required published-material errors still reject. |
| Draft and report | A learner without a learning record can still save a private answer. Teacher progress excludes draft text, raw chat and report. Answer/material/canonical conversation/return changes invalidate the report; a worker result cannot overwrite a newer version. Report generation reads the conversation directly and cannot depend on an assessment row. Revoking access to committed chat evidence after material reading but while the paid model is running must prevent a READY report. Revoking it after submission's outside-transaction material read but before its final transaction must reject atomically and preserve the draft. |
| Paired submission | Only a human click submits one immutable answer/report pair. Partial failure preserves the draft. Same idempotency/content returns the same submission; different content conflicts. Parallel requests do not duplicate versions. Pending replacements preserve history. |
| Teacher decisions | Only authorized teachers can pass/return the newest submission. Stale expectedSubmissionId conflicts. Passed work cannot change until returned. Return requires a new current report but existing learning records suffice; new demonstrated mastery is not a prerequisite. Any retained historical manual review preserves doubts and never fabricates mastery. |
| Concurrent transactions | A finishing model effect waiting for the actor must not deadlock with a draft update enqueueing the same effect; the newer generation remains pending and old results cannot validate it. A lease that expires while authorization locks are awaited cannot install a result, even if its token is unchanged; a fresh owner can recover. Manual review waiting for a learner must not deadlock with that learner saving a draft. An earlier-started RETURNED transaction that takes its locks after a completed PASSED decision must be the current decision and allow editing. No retry may duplicate model charges to hide a lock cycle. |
| Deadline and closure | Past due permits late submission with a genuine learning record. A submission whose transaction begins before the deadline but waits on authorization until after it must record its actual insertion time and a consistent late flag. Closure blocks first submission and ordinary revision; only a currently returned learner may refresh the report and submit once, consuming that exception. Participation does not bypass closure. |
| Privacy and compatibility | Peer/cross-course/cross-tenant, revoked membership, attachment access, teacher summaries and agent tools enforce the same boundary. Historical activity submissions remain usable. Experimental interactive lessons stay disabled. |
| Teacher conversation summary | The native overview must remain usable under its 8,000-character output limit with 20 long criteria, long submitted answers/reports and more than one learner page. Whole-class status/missing-criterion counts must not become page counts. Explicit report/answer pagination returns only submitted snapshots, excludes private drafts/internal hashes and is stable enough to reconstruct the visible section. Live teacher requests must execute the actual overview tool and produce a report-grounded summary that an independent judge accepts without fabricating deficiencies or changing decisions. |
| Learner native reads | Long criteria and answers must not overflow the same 8,000-character tool budget. Paged requirements recover every exact criterion, own answer sections recover the full private draft, and material sections contain actual extracted PDF/DOCX/text plus source hashes with a stable sourceVersion across pages. Unsupported/changed materials, revoked membership, another learner, another homework or a non-private conversation reject. |
| Real services | Live runner rejects absent credentials, same judge model, invalid prices, ambient product DB and unknown options before services/calls. Real worker, WuKong, extracted text/PDF/DOCX and public material receipts, measured shared-ledger usage and independent judge decisions are required; no fabricated DB mastery. |
| Rejected paid model output | A completed provider response that fails protocol validation remains a failed attempt but retains measured tokens and cost. Every paid attempt has exactly one ledger entry, including bounded corrections, and total input/output tokens reconcile with provider metering. Unknown or unmeasured usage cannot pass the live accounting gate. |
| Content-review diagnostics | A provider call can be measured and successful yet fail the runtime's stricter content-review grounding. Diagnostics must distinguish malformed shapes, absent/null fields and non-verbatim quotes using only bounded field types/counts/lengths, hashes and match booleans. Raw prompts, candidate bodies, findings and quotations must never enter logs or artifacts, including malformed/unexpected keys. Observation must not alter the actual request, response, runtime validation or metered usage. Self-checks cover valid findings, null blockedBy, absent requestQuote, ungrounded quotes and text-sentinel exclusion before this instrumentation is used. |
| Complete live paths and adversarial evidence | A struggling learner's incomplete first submission, a teacher-returned revision using the same learning record, and an already-proficient learner's brief interaction each produce a real answer/report pair. The initial partial report preserves deficiencies; revised reports do not invent new independent learning. Instructions embedded in an actual uploaded text attachment cannot fabricate mastery or submit/accept for a human. The actual report-model request must include the extracted attachment, proven by matching content hashes. An independent judge checks report honesty, assistance, independence, limited evidence and the teacher summary. At least one report must be model-verified; fallback-only execution cannot pass model acceptance. |
| Browser | Official `@e2e-dev/web` only: editable card/latest confirmation, private resume, locked draft, report preview/human submit, teacher return/review, attachment upload/recipient/reload, 390px light/dark, visible keyboard focus and no overflow. While draft validation is pending, hold an already-issued detail request, edit the title, then release the real response: the in-flight poll must not replace local edits or re-enable confirmation. |

Evidence is written beneath `artifacts/homework/<commit>/<run-id>` with source tree, command, timestamps, pass/fail/skip counts, public receipt/version IDs, measured usage and bounded judge conclusions. Secrets and raw private conversations must not be logged. Missing, skipped, failed or incomplete cases do not count as passed.

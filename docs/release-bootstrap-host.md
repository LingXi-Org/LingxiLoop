# Fixed host bootstrap (#495)

This module prepares Komodo terminal commands; it does not execute them. The sole production writer must run them on the already approved `shanghai-a` and `shanghai-b` hosts after verifying exact host identity. Commands intentionally contain public material only. Never wrap plaintext secret JSON in a terminal command, environment assignment, base64 payload or shell argument.

## Interface and order

Import from `scripts/release/bootstrap-host/index.mjs` in the credential-bearing operator process:

1. `buildInstallQueryCommand({opsSha})` reads fixed installation receipt, installed file hashes and current symlink. On an uncertain previous result, query first. An absent receipt or drift is not proof that installation did nothing.
2. `buildInstallCommand({opsSha,bundleSha256})` uses Python3 and the canonical `https://nodejs.org/dist/v22.23.3/node-v22.23.3-linux-x64.tar.xz`, pinned SHA-256 `df450af89261115ef9f9e3830c3eeb2cc9213b63c720b1af623cb5dcbe2e02de`. It downloads `https://codeload.github.com/LingXi-Org/LingxiLoop/tar.gz/<opsSha>` with an independently obtained archive SHA-256. The repository commit must be public/reachable first. TLS verification remains enabled; redirects fail. No credentials are sent to these download endpoints.
3. Run `buildPublicKeyCommand()` after the private Node binary is installed. It creates/reuses an X25519 keypair in `/run/lingxi-release-bootstrap-495/ephemeral.json`, directory 0700/file 0600; only the public SPKI key is returned. Preserve the complete public-key response and verify the target host/channel before encryption.
4. In the operator process only, call `encryptSecrets(publicKey, bundle, requestId)` with a fresh random 32-hex request ID. The helper creates a temporary cloud X25519 keypair, derives AES-256 via HKDF-SHA256, authenticates request ID/host-public-key hash, and emits an AES-GCM envelope. Bundle keys are limited to `executor-token`, `ingress-executor-token`, `access-client-id`, `access-client-secret`, `tunnel-token`. Values must be single-line secret strings of length 16–16384. Keep the envelope and request ID for reconciliation; discard plaintext and cloud private key from application references after use. JavaScript does not guarantee physical memory zeroization.
5. Execute `buildCredentialCommand(envelope)`. Only ciphertext, cloud public key, IV/tag and public identifiers cross the logged terminal boundary. Decryption writes exclusively to `/etc/lingxi-release/secrets/<allowlisted-name>` with 0600 permissions, fsyncs files, writes a hash-only receipt and removes the ephemeral private key. Output includes file hashes, never values. Existing different files cause a conflict; partial identical writes can be resumed with the original envelope while the ephemeral private key remains available.
6. If the result is unknown, execute `buildCredentialQueryCommand({requestId})` first: it returns hashes, matching receipt when present and the remaining ephemeral public key. A verified exact-envelope receipt makes repeating the same command idempotent even after private-key deletion. Do not generate replacement keys or overwrite credentials to conceal an uncertain outcome. `/run` is intentionally temporary: after reboot, if the key/receipt is gone, compare fixed file hashes against operator-held expected hashes and stop for reconciliation before any new handoff.
7. Supply a **non-secret** reviewed policy to `buildPolicyCommand(policy)`. It invokes the installed `validatePolicy`, requires loopback `127.0.0.1:17951` and fixed `/var/lib/lingxi-release`, then exclusively creates `/etc/lingxi-release/policy.json` (0600). Identical policy is idempotent; an existing different policy is rejected. Output is the policy SHA-256. Credentials belong in file references, never policy literal values or URLs.

`buildInstallCommand` installs only the official Node executable at `/opt/lingxi-release/node-v22.23.3-linux-x64/bin/node`, with private `/opt/lingxi-release/node` symlink; it does not install npm or alter global PATH. An existing Node installation requires its matching bootstrap-node hash receipt. The GitHub archive is hash-checked and only regular files under `scripts/release-host/**` and `deploy/release-host/**` are extracted into `/opt/lingxi-release/versions/<opsSha>/`. Archive traversal, links and unsupported file types are rejected. `current` is replaced atomically. The host service template's ExecStart is rewritten to the private Node path and installed as `/etc/systemd/system/lingxi-release-host.service`; no `daemon-reload`, enable, start, Docker action or product action runs. An existing differing unit or a partial version directory without an installation receipt causes an explicit stop for investigation. Installation receipts contain hashes for every installed bundle file, the Node binary and the unit.

The service and all fixed local-control argv in the reviewed policy must use the private Node executable with `--experimental-sqlite`. The archive checksum is for the raw GitHub archive, not the Git tree SHA or a local tarball regenerated from source. The installer modifies the version-local unit's Node path after archive verification and records its final installed hash.

## Authority and outstanding host facts

The user-approved scope is two hosts, executor loopback port 17951, release-a/release-b Tunnel + Access with restricted service tokens, separated credential classes and the approved backend origin. This module creates no Cloudflare token, connector, DNS record or Access policy, and provides no arbitrary remote executable/path option. The private Node path must exist before key exchange; it does not require a system Node installation.

Before policy provisioning, the sole integrator must fill and verify actual Compose project names, immutable source Compose/env file paths, current image identities, every durable named and anonymous mount, state directory, service roles, qualified native/product schema and checksums, database control identity/backup archive policy, shared gateway container/template/output paths, backend addresses/probes and secret file references. The example policy is not production inventory; its old example port and `/usr/bin/node` argv must be replaced in the reviewed non-secret policy. In particular preserve SurrealDB anonymous `/data` and `/logs` volumes identified in `docs/release-access.md`. Source paths and schema qualification must come from current host/database evidence; this bootstrap did not independently inspect them.

Mihomo, cloudflared installation, tunnel token consumption, service activation, gateway/backend setup and rollback remain separate approved host procedures owned by the integrator. Merely receiving credentials or an installation receipt does not prove transport readiness or release acceptance. Do not start the executor until policy, credentials and persistent paths are verified. Do not retire Komodo resources on the strength of this bootstrap alone.

## Owned upgrade transaction and interrupted promotion

The installer now supports upgrades from the original version-1 receipts. Before any promotion it verifies the previous `current` points to an exact version directory, loads that version's own `install-<sha>.json`, and checks its complete version file inventory, Node binary and current systemd unit hashes. An existing unit without that ownership evidence is rejected even when its contents match. An old unit may be replaced only when its current hash matches the previous own receipt. Both the legacy `/usr/bin/node` template and the private Node ExecStart template are accepted; the installed unit always uses the private Node executable.

`systemctl is-active lingxi-release-host.service` must prove the executor inactive/failed/not installed before staging/promotion and again before applying the promotion. An active, activating, deactivating or unqueryable service fails the command. Stopping and draining are explicit operations owned by the integrator; this installer does not stop the service or assert application drain evidence.

After staging and fsync, `install-intent-<opsSha>.json` is persisted before final Node/version/unit/current changes. It binds exact ops SHA, bundle SHA, previous current pointer/unit hash, staging directory and complete Node/version file hashes. Existing final version directories are resumable only with this matching intent and exact complete inventories. A mismatch, missing owner receipt, unowned partial version or different bundle is rejected; nothing is overwritten or deleted to force success.

Promotion validates every existing identity first, then promotes staged Node/version paths, installs the unit atomically, and replaces `current` atomically last. The intent covers the gap before the final receipt: after a crash with either the unit or current already switched, replay first verifies that all artifacts equal the intent and each external identity is either the exact previous or intended identity. Only then can it finish the pending promotion and final receipt. Old version directories, old receipts, intent and staging evidence are retained. An exclusive fixed bootstrap lock serializes production install commands.

For uncertain outcomes query both `/opt/lingxi-release/install-<opsSha>.json` and `/opt/lingxi-release/install-intent-<opsSha>.json`; a missing final receipt does not mean no effects. `install.py` exports `query_install(sha, root=ROOT, unit=UNIT)` for the command builder/test actor: it reads the receipt/intent/current and verifies available staged/final inventories, returning `verified`, `intentFilesVerified` and current unit hash. It performs no mutation. The operator's transport query must expose the intent when final receipt is absent; do not blindly rerun a previous non-transactional installer. For this upgrade, previous service credentials and any production policy remain separate from code installation.

Additional validation: `node --test scripts/release/bootstrap-host/install.test.mjs` runs five Python actor regressions in temporary directories with mocked Node/systemd identity: unit-switch and current-switch crash followed by query/verified continuation; version-1 receipt compatibility; active-service refusal; absent owner receipt/unowned unit refusal; existing partial version refusal; mismatched intent bundle/file drift refusal. No real host/service/download is used.

# Email and calendar retirement

Product email and calendar were retired in issue #117. Web, mobile, local Electron and administration share no mailbox/calendar entry, capability, tool or actionable card. Old `/api/email`, `/api/calendar` and `/webhooks/email` requests return `410 Gone`. Calendar Agent ingress is rejected; product email retries, calendar dispatch and email notification delivery no longer run. New Agent configurations reject both grants, and runtime context silently filters stale grants. The model receives only available capabilities and generic truthfulness rules; it has no feature-specific denial policy. Specific requests are answered from actual tools and observations, without a fixed product refusal template (issues #135 and LingxiOS #21 supersede that part of #117).

Migration `0034_retire_email_calendar` removes stored Agent grants and obsolete tool names, changes the default grants, cancels active/paused calendar events and pending email notification deliveries, clears email retry deadlines and fails outstanding calendar ingress/native events. It retains every historic message, event, attachment, receipt and audit row. WuKongIM messages replay as static title/body/time text with a retirement notice; old tool approvals and links have no product actions. Historic SQL permission/resource shapes remain only for backward-compatible row ownership and audit data, not an Agent capability. Existing LingxiOS jobs of kind `calendar` fail product context authorization before model/tools; no package internals are modified.

Operators may export or delete retained data only through a separately authorized retention operation. This release does not drop tables, bulk-delete history or remove stored attachment objects. Rollback requires deliberate code/config restoration; migration state does not re-enable grants, retry deadlines or schedules.

Account verification and password reset keep the control-plane SMTP provider. Organization invitations keep the Resend sending provider, `RESEND_API_KEY` and `EMAIL_DOMAIN`, with explicit failure on missing credentials. The provider is not registered with Agent tools and there is no receiving webhook configuration.

Reproduce product retirement coverage with `npm run test:integration -- --file retired-product-tools.test.ts`, capability protocol coverage with `--file agent-protocols.test.ts`, and official browser acceptance with `E2E_TELEMETRY_DISABLED=1 npx --no-install e2e run --config e2e.retire-layout.config.ts` (PowerShell: set the environment variable first). Browser output is in `artifacts/retire-layout/after`.

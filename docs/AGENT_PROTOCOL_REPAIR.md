# 智能体正文与能力链路修复

实现分支：`codex/agent-protocol-repair`。基于 `origin/main` 的 `6bc0c6e`，合并原本地 `fa9fff1` 的独有提交。原目录中的未提交修改保持原样；本次实现位于独立工作树。没有部署、推送或发布包。

## 定位结果

- 普通对话的自动快速模式确实只提供升级入口，并省略学习与知识上下文。模型所说“只有 response__upgrade”有实际配置原因，不能仅靠提示词要求它使用不存在的工具。
- 生产节点此前检查到的镜像为 `6f0e0c4`，虽然安装 LingxiOS 3.3.6，但不包含主线非思考修复 `8230621`。其中 App A 的部署记录失败；服务健康不能证明修复已上线。
- 提供商思考字段与 `content` 是两种不同问题。显式关闭思考、隔离推理字段后，真实 DeepSeek-V4-Flash 仍出现把内部答复规划写入 `content` 和重复结束语的情况。不能把它归因于前端 Markdown，也不能用裁剪或隐藏冒充源头修复。
- 能力默认值分散，文件能力缺少可调用接口。工具事件投影只留下状态，日历和评分结果无法形成完整卡片；历史分页及问答回复关联也会丢失展示状态。
- 全局短回复及学习预设中的最小提示策略，会让认真学习的用户反复追问。完整执行模式与正文长度是不同维度，二者均已调整。

## 实现边界

依赖声明、锁文件及安装版本固定为正式 `@lyyzka/lingxios@3.3.6`。迁移 0030 已负责 3.3.6 的安装记录；新增事务迁移 0031 只补齐普通在职智能体的十类业务能力，不修改历史迁移、不执行启动 DDL、不覆盖身份或自定义提示词。注册教师智能体排除在补齐之外，迁移之后的撤权持续有效。

最终采用硅基流动 `zai-org/GLM-5.2`，继续使用 LingxiOS 原生模型驱动和直接正文流。没有保留实验性的 JSON/最终回答函数适配层。配置示例、两节点 Compose 默认模型与 API 地址同步修改；已有显式环境值仍优先，发布时必须有意更新。计费使用[硅基流动官方价格](https://siliconflow.cn/pricing)的输入 8、缓存输入 2、输出 28 元/百万 token，并保留显式汇率与共享调用账本。

普通聊天固定完整执行，首次调用获得全部适用且已授权的工具及学习上下文。学习回答主动补齐概念联系、过程、实例、条件和误区；明确要求简短仍遵从。检索、委托和 Mission 按任务需要触发，不因解释较长而强制触发。

最终正文与 `chat.send` 共用正文检查，拒绝协议块、自述簇和重复段落，不按“思考”“我认为”等词截断正文。保持原有内容验收和直接流式展示。直接流式无法绝对阻止模型错误写入 `content` 的所有自然语言自述，真实提供商回归必须连同中间预览一起检查。

## 能力与卡片对应

| 能力 | 实际接口/承载方式 | 约束 |
| --- | --- | --- |
| 聊天、问答、建议 | `chat.send`、`chat.ask`、`chat.recommend`；持久 IM 问卷及回复 | 建议不表示已执行；内部子任务不能直接发到用户频道 |
| 投票 | `polls.*`；现有投票消息与交互 | 当前会话成员及投票权限 |
| 学习、Mission、评分 | `learning.*`；持久任务卡、评分展示 | 学习受众隔离；评分字段来自实际评价记录 |
| 统计 | `presentation.render` / `learning-stats` | 当前会话授权学习记录；注明为加载范围计数，非全课程总数 |
| 日历 | `calendar.*`；日历结果卡和可信展示 | 读取授权；写入审批；不使用模型虚构日程 |
| 邮件 | `email.*`；现有邮件及审批卡 | 保留邮件权限及发送审批；完整邮件结果不透传通用事件 |
| 文档 | `documents.*` | 保留版本检查和读回验证 |
| 文件 | `files.list/read/create`；原生下载产物 | 只读当前请求选择且仍授权的附件；文本读取最多 16k 字符/次，创建最多 128k 字符 |
| Canvas、交接 | `canvas.*`、`handoffs.*`；现有持久协作消息 | 当前成员、祖先授权交集及独立验证角色 |
| 知识、检索来源 | `knowledge.*`、`research.*`；来源卡 | 知识能力及 web 能力分别授权；来源结果白名单 |
| 演示文稿 | `presentations.*`、可信 presentation 卡 | 知识能力、实际项目记录、提纲审批及现有任务生命周期 |
| 定时任务 | `routines.*` | 原有调度、权限和幂等约束 |
| 目录、记忆 | `directory.*`、LingxiOS 原生记忆工具 | 原有租户、受众、记忆范围约束 |

服务端按白名单保留日历、评分、检索及必要状态；工具参数、提示词、完整文件/邮件内容不进入通用卡片事件。消息刷新、事件分页和重连合并沿用原生事件序号与调用身份，不重跑业务操作。

## 验证说明

真实提供商测试为显式 opt-in 的 `agent-protocols-live.test.ts`，只使用合成学习问题和独立测试数据库。记录首段可见时间、总耗时、模型调用次数、工具名称及检查结果，不打印凭据或系统提示词。场景包含大棚通信、TCP 安全性与局域网、RC 推导、课程材料缺失、文件与建议卡、明确一句话回答。

已完成的确定性检查：服务端单元测试 80 项、前端单元测试 79 项；前后端类型检查、修改文件 lint、Web 构建、服务端 Docker 镜像构建通过，镜像内实际 LingxiOS 为 3.3.6。迁移的 20 项检查通过，含重复执行、并发迁移、事务回滚及能力撤销保留。能力/课程上下文/学习预设及原有日历、邮件、知识、投票、协作和教师隔离集成路径已运行。两个测试等待窗口在重负载下失效，已改为有界等待异步任务就绪；完整模式和混合推理流两个运行时集成测试复测均通过。

卡片检查通过真实服务端 `publicRunEvent` 投影，再进入前端 `harnessToolParts`/`harnessParts` 并实际渲染日历和评分组件，检查白名单字段、模型参数不能伪造成绩、乱序历史合并、重放去重、执行中/失败/取消及待教师复核状态。问答回复以原始客户端消息身份关联并从持久消息恢复，同一用户对同一卡片的提交使用稳定幂等身份。

模型筛选中的失败也保留为验证结果，不能视为通过：

| 模型 | 观测结果 |
| --- | --- |
| DeepSeek-V4-Flash | 关闭思考后仍有 `content` 自述和反复结束语，淘汰 |
| GLM-5.3 | 提供商报告仍有推理 token，官方确认不支持非思考模式，淘汰 |
| GLM-5.2 | 早期预览检查失败；完整捕获后发现重复 Markdown 分隔线误报，已修正检测器并重新运行原生链路 |
| Qwen3.5-122B-A10B | 三个教学场景通过，工具连续调用遇到 HTTP 429，未通过完整链路 |
| Qwen3-30B-A3B-Instruct-2507 | 简单解释误启动 Mission，部分请求失败，淘汰 |

课程资料不存在时，允许诚实的 partial 结果；内容验收返回无效格式不能算通过。实时回归检查每次预览草稿，包括后来被纠正的草稿，不能只检查最终持久消息。直接流式与模型自然语言错误之间仍存在风险，不能据少量样本宣称绝对保证。

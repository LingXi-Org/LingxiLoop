# 双节点运行时验证

测量时间：2026-09-20T02:41:15.961Z。SDK 已发布版本为 3.3.0，提交 bf17f771f7560512aae779d54539c62b63b76782。

## 隔离性能测试

使用已发布的 3.2.13、3.3.0 公共接口、真实 PostgreSQL/Redis/MinIO，以及 Linux Bubblewrap Worker。各组预热 4 次，随后持续制造 6 请求积压，至少取得 30 次成功测量。每次运行固定模型 stub、相同预算和两次 Python 调用，创建 1MiB 文件、删除一个文件并提交 4 字节产物；从另一控制面读取产物并核对内容。

Worker B 限制为 0.75 CPU、512MiB、2 槽（预留交互 1 槽）；A 为 0.5 CPU、512MiB、1 槽（预留 0）。Python 各 1，模型并发为 2/1；启用与生产一致的性能选项和 750ms 空闲轮询。宿主为 Windows + Docker Desktop，结果不代表真实模型速度或生产网络延迟。

| 配置 | 成功/总请求 | 成功吞吐（请求/s） | 首正文 p50 / p95（ms） | 排队 p50 / p95（ms） | 模型正文→SSE p50 / p95（ms） |
|---|---:|---:|---:|---:|---:|
| 3.2.13 单 Worker | 35/36 | 0.37 | 7976.76 / 16976.15 | 7232.85 / 14094.25 | 14.45 / 24.80 |
| 3.3.0 单 Worker + 检查点 | 30/30 | 0.41 | 6977.54 / 14730.49 | 5796.46 / 12468.06 | 12.55 / 21.64 |
| 3.3.0 双 Worker + 检查点 | 30/30 | 0.62 | 5162.02 / 9072.70 | 3096.35 / 7693.87 | 16.39 / 27.50 |

双 Worker 相对同版本单 Worker 吞吐增加 52.22%。相对旧版，转发 p95 增加 2.70ms。旧版一次失败由虚拟机时钟回拨导致负模型耗时；失败及耗时保留在吞吐统计中，3.3.0 已改用单调时钟。旧版异常意味着不能把两个版本间的差异全部归因于检查点开销。

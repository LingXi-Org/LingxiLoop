# Native memory index maintenance boundary

Recorded before implementation. Use only the exact public LingxiOS 3.8.2 API and an existing product-authenticated company/principal/run binding. No production query, paid backfill, credential change or migration is performed by this development task.

Failures to reject before enqueue: absent or mismatched run identity; a scope from another tenant; duplicate or more than16 scopes; missing embedding configuration; inconsistent public current-index keys across scopes; invalid coverage counts; scope/key/eligible-count drift from the reviewed plan hash; an absent/invalid explicit eligible-record bound; or aggregate eligible records above that bound. Empty scope inventories or missing configuration cannot establish successful coverage. Re-resolve current authorization through the public API on every call. The public `doctor` owns the current key; the product does not import a private embedding driver or copy its key formula. Bind the named model to the separately verified effective runtime configuration and retain before/after keys.

Only `index-status` prints aggregate index state. The public `doctor` result also contains paths, document IDs, conflicts and other private diagnostics, so none of those fields may be copied to output. Output includes only configured model, public driver key, hashed binding/scope identities, counts and observation time. It does not search history, list runs, read a memory body through `read`, enumerate conversations or select an identity automatically.

`index-reindex` requires the exact plan hash from a prior status plus an explicit record bound. It calls the existing bounded public `reindex` once per approved scope and records submission/completion separately. A failed or uncertain call stops; no retry, alternate identity or remaining-scope continuation occurs. Enqueue acknowledgement never means embeddings are complete. Operators retain the receipt and obtain fresh status; current key coverage is complete only when every observed eligible record is indexed. This is scoped current coverage, not an atomic corpus snapshot or a claim of whole-production coverage.

Native 3.8.2 keys include endpoint, model, expected dimensions and optional index version. Native enqueue is limited to32 missing current-version/current-key records per scope; successful refresh schedules the next wave. Refresh checks active lease, fence, memory epoch/version, cancellation and current product authorization before writing. Its upsert is keyed by `(tenant_id,memory_id,model_key)`, preserving old-model rows. Existing root model budgets and usage ledger remain authoritative; this CLI does not call the Provider, rename vectors, issue runtime DDL, delete rows or reset scopes.

Focused executable CLI regressions must cover aggregate redaction, correct/partial/unconfigured coverage, key/scope/count rejection, plan drift, bounds, revocation, partial enqueue failure/no replay and all resource cleanup. They use synthetic public API responses, not private production material. A real old/new-key retention integration remains a separate package/product integration gate.

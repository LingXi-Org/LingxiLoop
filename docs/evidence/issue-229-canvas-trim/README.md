## Size limit and stop condition

If the isolated 12,496,273-byte gzip proxy translated one-for-one into an OCI-layer reduction, the whole image would be about **193,462,959 bytes**, or **6.47% below** the historical 206,838,733-byte image. This is an illustration, not a candidate OCI measurement or guarantee. The retained base/APT plus SPA layers alone are **134,507,942 compressed bytes**. A hypothetical 32% whole-image reduction from the historical image would target 140,650,338 bytes, leaving only 6,142,396 bytes for **all** runtime dependencies if those two areas stayed fixed; the current dependency layer is 70,347,423 bytes and contains several proven runtime consumers. Thus the prior ~32% *source COPY* reduction cannot be extended into a safe 32% whole-image claim through small dependency deletions.

This round stops with the one pinned, functional platform-only candidate. Further savings from source maps, telemetry versions, tokenizer formats, avatars or SPA assets need their own consumer and regression audits; a base/runtime or SPA redesign is a separate product change. No source, license, isolation support, diagnostic map or other runtime resource is removed to chase a percentage. #229 still requires controlled build/disk measurements and final configured acceptance; this draft does not close it.

# Existing public maintenance executor failure model

Written before the executor wrapper. Root alone performs production operations. The application candidate and existing source/template policy remain frozen.

Failures: wrong source container/image or policy, concurrent Komodo action, missing or ambiguous native update identity, transport uncertainty after submission, terminal failure, application partial completion hidden by process exit, duplicate/extra/unrecognized result marker, unsafe unbounded output, private identifiers/body/provider credentials escaping to native logs, false zero from missing run or denied current ACL, repeated scans inflating unique counts, intentional session/role scopes treated as legacy continuity, schema mutation or new identity/lease/fence creation, queued work mislabeled indexed, original container change, model-key coverage guessed from old embeddings, stale or incomplete scope coverage.

Controls: validated accepted source and sealed exact image plan; source-host/file/image/4healthycontainer guard; serial public RunStackService db-migrate only; native isolation flags/no deps/no pull; process hard timeout; fixed script hash and deterministic aggregate schema; script uses current existing binding and public readRunReference/memory API, passive runtime and no new run identity. Private candidate/run/scope identifiers stay in same process, output only fixed metadata/counts/reasons. Native Complete/success plus exact GetUpdate target/id/operation and complete marker mandatory. Unknown/partial outcome stops without automatic replay. Current ACL, native audience/epoch/source checks remain authoritative. Read existing scopes/doctor, execute bounded migrate/reindex only under existing authorization, preserve isolated items. Inspect is explicitly permission-checked maintenance dry-run, not strict SQL READ ONLY. Follow-up counts distinguish queued from indexed and complete eligible coverage from safe isolation.

No production fault injection. Local contract/source review first; read-only inspect result is reviewed before execute. Final evidence retains original attempts and actual terminal identities. Do not run concurrently with image preparation or deployment operations.

## Reviewed execution carrier change

The original db-migrate carrier is inapplicable because its existing Compose environment only contains database settings. No dummy settings or credential copying are permitted. Maintenance will run only after successful9a5 production acceptance, through the existing app-a/lingxiloop service definition and its complete environment, with the exact never-pull target template and no parameter env, volumes, ports, deps, wrappers or hooks. A dedicated native adapter permits only this fixed RunStackService one-off; the frozen general release transport is unchanged. Passive product control preserves the real resolver and creates no Worker/server loop, new identity/run/fence or provider request in the maintenance process. Existing Workers own normal queued indexing. A fresh read/cache guard binds final acceptance/raw input hashes, exact target hosts/config/templates/containers before and after.

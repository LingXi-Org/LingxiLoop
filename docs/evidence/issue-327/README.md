# #327: six selected agents cannot create a group

## Established root cause

Six selected ordinary agents are supported. Creation automatically includes the human caller, producing a seven-member group. Agent participant IDs are directory IDs; human participant IDs are the authenticated users' IDs.

The existing access resolver synthesizes active teacher project access for an active organization administrator (`server/src/modules/access/context-resolver.ts`). `requireWorkspace` accepts that access. Creation then included the caller in a directory query requiring persisted project membership for all humans, contradicting the permission resolver. An administrator with no explicit membership received `400 invalid_members` before conversation/binding persistence, even with six valid agents.

The regression reproduces that mismatch on a disposable migrated database. This establishes a source-level cause, not proof of the membership or HTTP result in the original private screenshot. No production or private conversations were inspected.

## Changes

- The eligibility query recognizes the existing active administrator rule only for the current caller; selected human peers still need active project membership in the current organization membership period. No memberships or persistent grants are added.
- Group creation accepts an optional request ID. A deterministic conversation identity scopes it to company, project and creator; a PostgreSQL transaction lock serializes concurrent retries. The durable binding stores a hash of the original normalized selection/title, rejecting reuse with a changed group payload. Unkeyed API calls and new intents can intentionally create another group. No schema change is needed.
- The dialog retains the same request ID and selections after failed creation. Selection errors carry typed API codes and safe Chinese copy. Local unavailable selections disable submit with a clear explanation. Existing double-submit, workspace-generation and unmount protection remain active.
- Conversation and binding commit together. An external channel sync failure still leaves the binding for the existing reconciler; retry returns the same group.

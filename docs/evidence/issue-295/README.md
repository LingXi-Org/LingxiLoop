# User-facing diagnostic copy removal (#295)

System waiting/delivery prose was generated by `observedProgress` and serialized as
`observed-progress:<request>:<fence>` commentary. It therefore appeared in expanded
activities and replay even when no answer existed. New projections no longer create
these parts; the shared message decoder filters their recorded identity in existing
and nested assistant messages. Stored history and genuine answer/process text stay intact.

The waterfall no longer prints internal timing/availability explanations or empty
input/output sections. Tool receipt and error copy is actionable, including replay
of the old generated visualization receipt. Normal tool details, approvals, loading
animation, public activity and answer streaming remain. Timing and cost data fixes
are separately tracked in #296; this change does not make missing values known.

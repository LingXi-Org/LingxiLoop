# Early answer prompt alignment

The formal 3.8.8 synthetic qualification delivered a usable diagram, but its first
durable answer arrived after the save completed. Tool-turn provider content was
unframed prose; the native companion boundary intentionally withheld it. The
product instruction to use “ordinary response text” is ambiguous alongside the
native requirement that visible text be in the declared `answer` field. This is
a prompt ambiguity supported by code and observed structure, not proof of the
model's private decision process.

The small product change must fail verification if:

- Selected-skill and initial host guidance use different public-text channels.
- Guidance treats plain companion text as an accepted answer or weakens parsing.
- It requires a separate preamble call, repeats already delivered content, or
  allows a future tool result to be claimed before its real receipt exists.
- It loses activation, exact readback, authorization, or final-reference checks.
- Changed behavior retains the previous skill or harness binding identity.
- The vendored upstream skill is modified instead of the external host adapter.

The owning prompt regression inspects both real assembled prompt paths, checks
their protocol-field guidance and identity changes, and retains existing skill
loading/revocation/readback tests. This is a configuration regression, not proof
of model compliance. A new bounded real qualification remains necessary after
the coordinated upstream change. The original failed receipt is retained.

The complete channel/grounding guidance belongs to the always-assembled product
harness. Initial visualize host rules and the selected skill adapter refer to
that contract briefly. The regression checks initial, selected and restored
assembled prompts, including exactly one copy of the complete guidance; the
existing 64 KB full-skill limit is unchanged. Native tool lifecycle events already
provide ordinary activity. Separate progress calls remain available for useful
plans, material changes or failures needing attention, with existing task identity.

注意力机制 · 计算与显存

FlashAttention

一句话：它不改变注意力的数学结果，而是改变"怎么算"——把 $QK^{\mathsf T}$ 这样的大矩阵切块，边算边用，让显存访问成为瓶颈时不再被读写拖住。

01

先看清楚它在算哪一步

标准注意力对每个 token 的查询向量，都要与序列中所有键比较，再对值做加权求和：

\[ \operatorname{Attention}(Q,K,V)=\operatorname{softmax}\!\left(\frac{QK^{\mathsf T}}{\sqrt{d_k}}\right)V \]

式中有两个容易忽略的形状事实：第一，$\frac{QK^{\mathsf T}}{\sqrt{d_k}}$ 是 $N\times N$ 的分数矩阵，序列长度翻倍，它就变成四倍；第二，softmax 需要整行归一化——要对第 $i$ 行的全部分数求最大值和求和，才能确定权重。显式实现通常就把这个 $N\times N$ 矩阵写进显存并来回读几次，长序列下它就是显存与带宽的主要开销。

02

tiling：分块计算，全程只保留一个小矩阵

把 $K$ 和 $V$ 按列切成块 $K_j$、$V_j$，对 $Q$ 的一块 $Q_i$ 逐个处理：取出一块，算出这一块对应的分数，立刻用它更新输出，然后丢弃，再拿下一块。整个过程只在片上留下 $Q_i$ 的块级输出和归一化所需的两个统计量，完整的 $N\times N$ 分数矩阵从未被完整写出。

块 1
载入 $K_1,V_1$
算出块内分数，得到初版输出与统计量
块 2
载入 $K_2,V_2$
新的更大分数 → 旧输出按比例缩放后累加
块 3
载入 $K_3,V_3$
同理更新，最后除以总权重得到确切结果

难点在于第二步：新块可能带来更大的分数，而 softmax 的指数对最大值敏感。如果直接按旧最大值归一化，数值会溢出或失真。于是需要一个能"在线更新"的归一化方式。

03

在线 softmax：只带两个数走完全程

对每一行，维护当前见过的最大值 $m$ 与指数和 $\ell$。处理到新的一批分数时：

\[ m'=\max\!\left(m,\ \max_j s_j\right) \]
\[ \ell'=e^{\,m-m'}\,\ell+\sum_j e^{\,s_j-m'} \]
\[ O'=e^{\,m-m'}\,O+\sum_j e^{\,s_j-m'}\,V_j \]
最后 $O=\dfrac{O'}{\ell'}$，即得到与一次性计算完全一致的输出。

每个块新算出的权重都要乘 $e^{\,m-m'}$ 与旧结果对齐尺度——这就是"重标定"。它保证无论块按什么顺序到达，最终都等于全局 softmax 的结果。代价是每处理一块都要做一点额外乘法，但相比省掉的显存读写，这笔账很划算。

04

为什么省的是显存带宽，不是乘法

分块并没有减少必须做的乘加次数——依然是全部 $Q$ 与全部 $K$ 的比较。改变的是数据流：分数块在片上产生、消费、消失，不再写回显存、也不需读回来做 softmax 和再乘 $V$。当 GPU 的算术单元远快于显存带宽时，瓶颈就落在"搬数据"上；分块把搬运次数的数量级压下来，整体速度随之提升。

显式注意力
写 $N\times N$ 分数 → 读回做 softmax → 再读权重乘 $V$，中间量进显存
FlashAttention
分数在片上产生即用，只把 $Q$、$K$、$V$ 与最终输出放在显存，额外显存随序列长度线性增长
05

反向传播要重算，而不是存下来

训练时需要梯度。常规做法会把前向的中间矩阵留给反向用；既然这些矩阵本来就不存，就换个思路：反向时重新分块走一遍前向，在片上重建需要的分数，再算梯度。额外的计算换来了显存占用的大幅下降，这正是长序列训练能装下更大 batch 的关键。

记忆点：前向省显存；反向用重算换显存。两件事都建立在同一个前提上——分数块可以随时被重新生成。
06

代价与适用边界

换来什么
中间矩阵不再落显存；注意力计算更受限于算力而非带宽；结果与标准注意力数值上等价
付出什么
实现复杂（手写核函数、块大小调优）；反向多一次前向计算；需要硬件能高效做片上分块计算
不解决什么
算术量仍是 $O(N^2 d)$；它优化的是访存效率，若你的场景瓶颈不是显存带宽，收益会缩小

检验自己是否理解：给定块 1 得到 $m=2,\ \ell=3$，块 2 的最大分数为 $5$，那么重标定系数是 $e^{\,2-5}=e^{-3}$，旧输出与旧指数和都要乘上它——这一步正是"分块算"与"整行算"等价的桥梁。

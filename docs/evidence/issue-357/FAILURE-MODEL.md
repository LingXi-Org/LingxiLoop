# First useful text: context preparation failure model

- Authorized knowledge retrieval waits behind unrelated roster, learning, Canvas, visualization-state or memory-scope reads before the first model request.
- An independent branch failure must prevent the assembled context from reaching the model; concurrency must not turn a denied read into partial authorization.
- Cancellation during retrieval must reject with the original cancellation rather than become an unavailable-source result.
- Agent read receipts retain their existing transactional/outbox semantics and are never acknowledged before persistence.
- Knowledge retrieval still observes the current audience/source permissions, exclusions and versions. No permission, evidence or user context is cached across turns.
- Context preparation finishes only when its required branches finish; an early search start is not early model execution or a placeholder answer.
- Real timestamps and measured durations are distinguished from controlled test delays. Existing provider-first-content timing can include process text; it does not prove browser first useful answer paint.

The owning real PostgreSQL/local HTTP integration is extended before implementation. A held roster must not delay independent authorized search, but the overall context must stay pending until the roster is released. Existing timeout, cancellation, cross-read authorization and durable-receipt checks remain required.

## On-demand first-turn retrieval

- Having knowledge tools or enabled room sources does not mean every ordinary
  answer needs an external search before the model can respond.
- A direct ordinary answer must load its current authorized context without any
  automatic text/vector search; available knowledge tools remain available when
  the actual answer requires course or case evidence.
- Registered learning/homework/case workflows, Canvas work, delegated/internal
  work, background jobs and committed request attachments keep their conservative
  retrieval path. The decision comes from trusted context bindings and structured
  request state, never natural-language keywords or model claims of permission.
- On-demand is not a no-sources/unavailable result. An explicit search failure,
  source exclusion, version conflict or reader revocation remains visible and
  authoritative when evidence is requested.
- Current attachments and learning materials still require authorized reads;
  removing unsolicited search cannot fabricate their contents or drop a material
  reading obligation. No new model classifier, fast model or reduced budget is
  introduced.
- Changed preparation rules must change the product harness identity; old work
  resumes with its pinned deployment or is drained before rollout.
- Revisions can add attachments to the durable request without changing original
  work metadata. A revised ordinary turn must retain required preparation.

## Real-provider development qualification

- Measure actual durable answer events, not commentary or placeholders, and
  distinguish recorded event time from browser paint and provider first-token time.
- A requested explanation of two invented stages must appear before saving their
  interactive diagram; an attempted tool is not saved or authorized delivery.
- Retain the official browser check of the real saved diagram and delivered
  assistant reference. A standalone synthetic document is not this qualification.
- The following ordinary arithmetic request must use one generation, no knowledge
  search despite an authorized enabled source, no semantic judge and no inherited
  visual authoring obligation. Knowledge provider fixtures are counted locally.
- Automatic word coverage only locates a candidate explanation; independently
  review its actual role attribution and tense before accepting useful-answer
  timing. Approval waiting is not a successful save completion.
- Record failed measurements honestly, use one fixture run with one provider
  attempt per logical call, and never replay a failed original production request.

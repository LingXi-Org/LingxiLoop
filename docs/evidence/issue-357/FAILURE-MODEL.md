# First useful text: context preparation failure model

- Authorized knowledge retrieval waits behind unrelated roster, learning, Canvas, visualization-state or memory-scope reads before the first model request.
- An independent branch failure must prevent the assembled context from reaching the model; concurrency must not turn a denied read into partial authorization.
- Cancellation during retrieval must reject with the original cancellation rather than become an unavailable-source result.
- Agent read receipts retain their existing transactional/outbox semantics and are never acknowledged before persistence.
- Knowledge retrieval still observes the current audience/source permissions, exclusions and versions. No permission, evidence or user context is cached across turns.
- Context preparation finishes only when its required branches finish; an early search start is not early model execution or a placeholder answer.
- Real timestamps and measured durations are distinguished from controlled test delays. Existing provider-first-content timing can include process text; it does not prove browser first useful answer paint.

The owning real PostgreSQL/local HTTP integration is extended before implementation. A held roster must not delay independent authorized search, but the overall context must stay pending until the roster is released. Existing timeout, cancellation, cross-read authorization and durable-receipt checks remain required.

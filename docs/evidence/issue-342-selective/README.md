# Focused review for a selected visualization workflow

An exact current registered `skills.load` or `visualize.read_reference` of
`SKILL.md` nominates one narrow semantic review when native authoring has not
been activated. The review evaluates whether the current human request requires
creation/modification or only documentation, reading or export. Loading alone
creates no authoring obligation and grants no permission.

The selector consumes public native current-request execution steps, authorized
skill indexes, available actions and activation records. Prompt loading and this
selector share one exact argument/registry matching function. Current native
activation bypasses this judge and retains deterministic delivery verification,
including its existing honest unavailable-contract outcome. Native saves always
activate transactionally, so that path also covers current saved resources.
Revoking a selected unactivated workflow fails closed rather than silently
removing its review requirement. No user/assistant body is matched with a regex.

The constant trusted rubric, scope identity and new harness version participate
in the profile hash. The native policy id/version also bind execution; native
final commit independently requires current candidate/request/rubric identity.
Product wiring only adds the public control-plane `semanticReviewPolicy` option.
Worker selective mode and the formal runtime dependency are integration-owned.

Failure cases and tests were written before implementation. Focused product
selection/loading tests pass 12/12 and server lint passes. The Worker test covers
ordinary zero-judge output, a read-only load with one judge and no activation,
creation after load/promise, the SKILL.md reference route, explicit disabled mode
remaining partial, and an activated resource using no judge. The creation path
omits its checked reference once and must repair it without another save/version.

Those Worker cases and public API typechecking require the forthcoming formally
published runtime 3.8.4. They have not been reported as passing against 3.8.3.
Use dedicated local `runtime342_selective_test` and Redis database 12 for that
proof, separate from the integrator's real-provider fixture. This work made no
live provider call, production change, schema mutation in runtime code, permission
change or budget increase. The remaining no-workflow-selection language boundary
is outside this focused gate; universal natural-language detection is not claimed.

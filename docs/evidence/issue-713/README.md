# Design 逐页加载修复证据

关联 #713；产品基线 `2fc8d37369856e03a61c5249bf20c008481594b5`。本次没有部署。

## 原因与调整

- 页面 HTTP 接口原来调用智能体快照读取器，每取一页都会读全局清单及版本索引，随后丢弃这些信息。改用已有的单页读取器；仍先授权，再校验指定稿件、页面与历史哈希的归属。
- 文档首包包含第一个画布正文与属于该画布的首个画板。点击切换画布时立即请求正文；其余页面仍由可见区域驱动，页面请求使用浏览器高优先级提示。
- 元素注册、校验、可见查询由三个串行 Worker 往返合并为一个原子任务，多个画板同时提交。矩形用 Float64Array 打包，通过 Transferable 传输独立副本，保留主线程缓存。Worker 索引仍最多八页，几何未改时复用索引及校验结果。

## 可重现回归

使用 Node 24.19.0、系统 Chromium、相同公开依赖。私有 SDK 在本机不可安装，完整类型检查与产品集成交由安装正式 SDK 的 CI；没有引入替身依赖。

1. `node --import tsx --experimental-test-module-mocks --test server/src/modules/artifacts/native-page-router.test.ts`：先在旧路由复现失败，再验证修复。50 页、20,000 条全局版本键；内存存储夹具，不包含真实数据库与网络往返。旧路由读清单 50 次、总读 41,688,660 字节；新路由读清单零次、总读 19,810 字节。单次样本请求 p75 为 13.49 → 1.86 ms，仅作定位证据。授权拒绝、错误历史归属、无效哈希都不读取正文。
2. `node scripts/native-design-worker-profile.mjs <基线检出目录> <输出文件>`：实际构建两份 Worker，50 画板 × 500 矩形，10 组交替 AB/BA；断言结果相同。完整样本见 [worker-profile.json](worker-profile.json)。此文件记录开发候选的状态，不冒充冻结提交测量。冷几何 p75 27.78 → 9.92 ms，消息 150 → 50；八页重复视口 p75 0.473 → 0.175 ms。仅几何计算管线，不等同浏览器启动、脚本传输或 PSS 资格。
3. `PLAYWRIGHT_MODULE=<模块路径> node --import tsx scripts/native-editor-ui-acceptance.mjs --mode=design --checks=viewport-loading --browser=/usr/bin/chromium --output=<目录>`：真实 React、Worker、HTTP 夹具，遍历全部 50 页并返回已读页。正文复用、无额外写入、未修改页面哈希、过期视口不加载、离屏裁剪都通过；峰值仅七个节点。浏览器内从滚动到正文/图片/公式就绪后下一帧，完整结果见 [browser-page-loading.json](browser-page-loading.json)。单组基线/候选 p50 80.6/80.7 ms、p75 80.9/96.5 ms、p95 182.4/214.2 ms，回访 64.1/63.2 ms。该 HTTP 夹具绕过实际后端瓶颈，本组没有证明整体绘制提速，候选尾延迟也未改善；不据此宣称整体性能门槛通过。

此前通过外部浏览器轮询计时的试跑受自动化往返影响，没有作为正式浏览器证据。未打包的原子 Worker 版本在重复视口场景退步，随后采用传输缓冲区并重新测量；运行时代码只保留最终单一路径。

## 验收范围

新增正文路由回归、首包画布归属、50 页索引淘汰、几何版本拒绝、传输后缓存不被分离等测试。原生编辑器与共享模型聚焦测试共 432 项通过；独立传输测试三项通过。其他最终检查与独立只读审查以 PR 和精确提交的 CI 为准。

真实授权环境的跨租户集成、线上网络加载、整机内存与输入 p95、原 #707 的十组完整浏览器性能门槛不由上述夹具代替，不能登记为通过。本修复不改变持久化模型、草稿或撤销链路，也不新增服务、依赖和数据库结构。

## Seed and environment boundaries

The existing public migrator also performs `ensureEducationPlan` upserts. It is **not read-only**: the query ensures those writes preserve the existing logical values; even equal values may incur physical UPDATEs. Seven committed source definitions must match the reviewed canonical source and target bytes. The fixed query compares exactly one plan, eight entitlements and eight plan-entitlements and emits only counts/hash/booleans. Missing, changed or incompletely visible values fail before service stop. No ensureEducationPlan call is used for the check. This read-only snapshot is not a concurrent administrative-write lock; the sole release owner must preserve the release's no-concurrent-maintenance boundary.

New public-text plans contain `imageConfigs.source` and `.target`, the exact UTF-8 raw **public OCI image configuration** bytes from the two audited images. Their SHA256 must equal each descriptor's audited config digest. Non-Env startup configuration and every baked Env key except commit/NODE_VERSION must match. Node remains major22. Every actual cached host image Env must match its audited public config, and every container must declare the exact corresponding Node version. Only this derived NODE_VERSION value is normalized for per-service comparison; duplicate keys, unknown sources, other environment/security/startup/volume changes fail. Secret-bearing service environment values stay in memory. These fields never contain live service configuration or credentials.

The old same-schema profile remains limited to its original reviewed versions; it cannot admit3.7 just because schema14 is unchanged. The actual d601 interrupted-release acceptance format is supported directly as a reader-phase source. Its original failed attempt is neither modified nor synthesized into a successful straight-line history.

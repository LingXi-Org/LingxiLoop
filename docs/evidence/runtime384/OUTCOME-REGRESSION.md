# Same-generation outcome qualification

The formal 3.8.4 owning test reproduced a release blocker: an ordinary
purpose-json-v1 answer accurately disclosed that requested actions were not
performed, but its goal outcome was `satisfied`. No tool had been admitted and
no trusted selected workflow existed, so the deterministic runtime had no
machine-readable negative declaration. The non-satisfied assertion is retained.

Before enabling a new formally published runtime, qualify these boundaries:

- The producer explicitly selects purpose-json-v2. The public event reader stays
  version 2; changing the provider framing must not silently alter v1 parsing.
- One ordinary generation can declare satisfied, partial or blocked. A negative
  declaration retains its public missing-result explanation without another
  model judge or an automatic full-answer rewrite.
- Structured metadata cannot replace authorization, artifact ownership,
  cancellation, budgets or actual effect receipts. A satisfied declaration
  cannot override a deterministic failure or an unknown effect.
- Negation, quotations and conditional prose do not determine completion through
  keyword matching. The typed declaration is validated separately from prose.
- Tool-only turns do not need a fabricated final answer. Truncated or invalid
  terminal framing is a real protocol failure; completed effects are not replayed.
- Provider metadata never appears as an ordinary answer fragment. Useful answer
  streaming, exact call metering and identical-text/new-message identity remain.
- A final real-provider development check must deliver an actual usable visual
  resource and then answer an ordinary question in one measured generation.

3.8.4 is published and immutable. Production remains on 3.8.3 while this blocker
is fixed in a new upstream version. Fixture preparation and draft CI are not
production acceptance.
